# 官方服务示例（可导入的服务配置）

这里放的是**服务配置示例**：侠影 App v0.132.0 起的服务定义导入/导出格式
（外层 `{"services":[...]}`，字段与 App 内导出 JSON 逐字一致），复制全文粘贴
到 App 里就能导入成一个服务条目，再在服务页里启动/改参数。

注意区分：这里是**配置文本**，不是插件包，不在插件市场里、不能一键安装。
真正的插件包在市场（`market.json`）里。其中 **hello-service 示例服务**是
市场在架的 zip 服务包（见仓库根 README 条目表），装上就能跑，不需要导入配置。

## 示例清单

| 文件 | 服务 | 依赖 | 状态 |
|---|---|---|---|
| `t4-php.service.json` | T4-PHP 站点源 Web 服务（端口 29578） | PHP 运行时插件 | 运行时**待上架**，配置先行 |

## t4-php：PHP 站点源服务

- **干什么的**：用 PHP 内置服务器（`php -S`）跑一个站点目录，形态与 DsPlayer
  的 T4-PHP 一致：打开服务地址是状态页，`/config.php` 输出 T4 源列表，
  把 `http://127.0.0.1:29578/config.php` 添加为侠影的订阅地址即可用里面的站源。
- **前置条件**：PHP 运行时插件（提供 `__plugin:php__/bin/php`）。该插件尚在
  制作中、未上架；未装运行时就导入本配置，服务启动时会明确报
  `__plugin:php__ 未安装`，属于预期提示，不是配置写错。
- **站点目录**：配置里的工作目录是 `__sdcard__/php/t4_demo`，即手机公共存储
  的 `xiaying/php/t4_demo/`。把 T4 的 PHP 脚本放进这个目录，服务就能跑到它们；
  目录不存在时 App 保存配置会先建好空目录。
- **端口**：侠影用 **29578**；DsPlayer 同款服务用 19978。刻意错开，两边同时
  装不冲突；不建议改成 19978 与 DS 抢同一个端口。

## 导入方法

1. 打开示例文件（如 `t4-php.service.json`），复制全文。
2. 侠影 App → 插件中心 → 「服务」页签 → 导入 → 粘贴 → 确认。
3. 导入后服务出现在列表里，点开可看/改全部参数（命令、参数、工作目录、
   环境变量、探活方式、自启动），改完保存即生效。
4. 与已有服务重名时 App 自动改名加后缀（`-2`、`-3`…），不会覆盖已有服务。

## 端口对照（侠影 vs DsPlayer）

| 服务 | 侠影 | DsPlayer |
|---|---|---|
| T4-PHP | 29578 | 19978 |
| 示例服务 hello-service | 29578 | —（DS 无对应） |

hello-service 与 t4-php 声明的都是 29578：两个服务同时安装时，App 分配端口
会让后装的一个自动顺延（29579 起），以各服务卡上显示的实际端口为准。

## 没提供的示例（及原因）

- **drpy 类服务**：不需要。侠影的 drpy 规则由 App **内置 V8 引擎**直接执行，
  根本不用起 Node 服务；DS 需要 drpys 是因为它的引擎路线不同，别照搬。
- **Node 运行时已搁置**，依赖它的磁力转播示例暂不提供。
